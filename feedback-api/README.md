# SNACks feedback API

This Cloudflare Worker accepts anonymous feedback from `bimsnacks.no` and creates a public issue in this repository. GitHub Pages never receives a GitHub credential.

## Data flow

1. The React widget sends category, description, page context, an idempotency key, and a Turnstile token.
2. The Worker checks origin, payload shape/size, allowed page host, honeypot, and Turnstile.
3. D1 atomically enforces a submission rate per keyed IP hash and prevents immediate duplicate submissions.
4. The Worker obtains a one-hour GitHub App installation token and creates a labeled issue.
5. The browser receives only the public issue number and URL.

D1 stores no feedback body, name, email, or raw IP address. Guard records expire after 24 hours; rate-limit records expire after two windows and are deleted opportunistically.

## Free Cloudflare setup

Prerequisites: Node 20+, a Cloudflare account, permission to create a GitHub App for the organization, and `gh`/GitHub repository administration access.

1. Install dependencies:

   ```powershell
   Set-Location feedback-api
   npm ci
   ```

2. Authenticate Wrangler and create D1:

   ```powershell
   npx wrangler login
   npx wrangler d1 create snacks-feedback-guards
   ```

   Replace the all-zero `database_id` in `wrangler.jsonc` with the returned ID. Apply the schema:

   ```powershell
   npx wrangler d1 migrations apply snacks-feedback-guards --remote
   ```

3. Create a free Turnstile widget for `bimsnacks.no`. Put its public site key in the repository Actions variable `TURNSTILE_SITE_KEY`; keep its secret for the Worker.

4. Create a GitHub App owned by `Infrastructure-Consultancies-in-Norway`:
   - Repository access: only `Infrastructure-Consultancies-in-Norway.github.io`
   - Repository permission: **Issues: Read and write**
   - Webhooks: inactive

   Generate a private key and note the app and installation IDs. Installation tokens are short-lived and generated by the Worker. The Worker expects an unencrypted PKCS#8 key (`-----BEGIN PRIVATE KEY-----`). If GitHub supplies a PKCS#1 key, convert it before storing it:

   ```powershell
   openssl pkcs8 -topk8 -nocrypt -in github-app.pem -out github-app.pkcs8.pem
   ```

5. Store Worker secrets interactively:

   ```powershell
   npx wrangler secret put TURNSTILE_SECRET_KEY
   npx wrangler secret put RATE_LIMIT_SECRET
   npx wrangler secret put GITHUB_APP_ID
   npx wrangler secret put GITHUB_APP_INSTALLATION_ID
   npx wrangler secret put GITHUB_APP_PRIVATE_KEY
   ```

   Generate `RATE_LIMIT_SECRET` with a cryptographically secure random generator. Never commit `.dev.vars`, a private key, or a token.

6. Run the `Configure feedback labels` workflow once.

7. Add `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` to the protected `feedback-api` GitHub environment. Limit the Cloudflare API token to editing this Worker and D1 database.

8. Run `Deploy feedback API`. Set repository Actions variable `FEEDBACK_API_URL` to the deployed Worker origin, with no trailing slash. Deploy the Pages site afterward.

Cloudflare's documented test keys may be used in `.dev.vars` and `.env.local`; production keys must not be used for automated tests.

## Local development

Copy `.dev.vars.example` to `.dev.vars`, replace its values with development/test credentials, and update the D1 ID if necessary.
The example also overrides the production Turnstile action and hostname checks with
the values returned by Cloudflare's official dummy keys (`test` and `localhost`).

```powershell
Set-Location feedback-api
npm run dev
```

In `snacks-app/.env.local`, configure:

```dotenv
VITE_FEEDBACK_API_URL=http://localhost:8787
VITE_TURNSTILE_SITE_KEY=1x00000000000000000000AA
```

Then start the app from `snacks-app` with `npm run dev`.


## Operations and rollback

- **Disable submissions:** set `FEEDBACK_ENABLED` to `"false"` in `wrangler.jsonc` and redeploy. The widget reports the unavailable state without claiming success.
- **Rotate credentials:** replace each Worker secret with `wrangler secret put`. Rotate the GitHub App private key before deleting the old key.
- **Change limits:** adjust `RATE_LIMIT_MAX` and `RATE_LIMIT_WINDOW_SECONDS`, then redeploy.
- **Monitor:** use Workers Logs for safe error summaries and GitHub's audit log for app-created issues. Logs intentionally omit feedback text, tokens, and raw IPs.
- **Free-tier exhaustion:** Cloudflare can reject requests after a free daily limit is reached. The browser shows a submission failure and retains the typed description in the open form.
- **Turnstile outage:** submissions fail closed; no GitHub issue is created.
- **GitHub outage:** the idempotency reservation is released so the visitor can retry with a fresh Turnstile challenge.
- **D1 outage:** submissions fail closed before calling GitHub.

The browser origin allowlist and CORS are not authentication. Keep Turnstile, server-side validation, D1 throttling, and the kill switch enabled.
